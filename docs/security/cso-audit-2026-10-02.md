# Security review — 2026-10-02

Scope: source review and regression tests for request handling, game-builder
input, static assets, local serving and CI permissions. This is a focused
review, not a penetration test or a full history/secret audit.

Verified fixes:

- JSON bodies stop reading and cancel the stream at the byte limit, including
  requests without Content-Length. Media types must be application/json.
- Custom game-builder fields are escaped when inserted into HTML and results.
- Local serving binds to loopback by default and excludes dotfiles, backend
  source, scripts, operator notes and tests. Public assets and HEAD still work.
- Deployment stages only public assets. Previously the live site served
  context.md with HTTP 200 because the repository root was uploaded.
- A database failure after accepting a score returns a generic 503 response.
- CI explicitly limits its token to read-only repository access and runs the
  security tests. Deployment runs those same tests before uploading.

Evidence: npm test; npm run test:security; public-build manifest assertions;
live checks recorded after deployment. The unrelated Pac-Man test edit is
excluded from this change.

Remaining limits: leaderboard scores originate in the browser; ceilings and
one-use sessions limit submissions but cannot prove honest gameplay. CSP still
allows inline scripts. This review did not verify secret rotation or search
the full Git history. These limits must not be represented as completed work.
